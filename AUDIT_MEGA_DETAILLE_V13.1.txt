============================================================
1. VERDICT GÉNÉRAL
============================================================

La V13 avait une base technique solide : aucun effondrement général du JavaScript, 24 modules complets, navigation interne fonctionnelle, stockage local déjà protégé par normalisation et sauvegardes, et une PWA opérationnelle.

L’audit approfondi a toutefois révélé plusieurs défauts invisibles lors d’un simple parcours manuel :
- biais très important dans la position des bonnes réponses des QCM ;
- risque de perdre le vrai point de retour lors d’un import complet ;
- installation PWA trop dépendante du préchargement du gros fichier musical ;
- gestion insuffisante des requêtes audio partielles hors ligne ;
- incohérence des limites d’objectifs hebdomadaires après import ;
- une traduction réellement incorrecte / trompeuse de « fair enough » ;
- trois références vidéo impossibles à confirmer de façon fiable lors de l’audit ;
- quelques détails d’accessibilité mobile et de cohérence de version.

Tous les défauts ci-dessus ont été corrigés dans cette V13.1.

4. SAUVEGARDE, IMPORT ET STOCKAGE LOCAL
============================================================

4.1. Bug de point de retour avant import — CORRIGÉ

Ancien comportement :
- la page créait une sauvegarde PRE_IMPORT de l’état actuel ;
- puis restaurait tout le JSON ;
- si ce JSON contenait lui-même une ancienne clé PRE_IMPORT, cette ancienne clé écrasait le point de retour fraîchement créé.

Conséquence : après un import, la fonction de récupération pouvait revenir vers une ancienne sauvegarde au lieu de l’état qui venait réellement d’être remplacé.

Correction :
- restauration du fichier importé d’abord ;
- écriture EN DERNIER de l’état courant dans PRE_IMPORT.

Test automatisé :
- état avant import = CURRENT ;
- état importé = IMPORTED ;
- ancienne sauvegarde dans le JSON = OLD_IMPORTED_BACKUP ;
- résultat V13.1 : état principal = IMPORTED, point de retour = CURRENT. OK.

4.2. Export vide — CORRIGÉ

Si aucune donnée Nathalie n’existe :
- le bouton Export est désormais désactivé ;
- le texte explique qu’il n’y a encore rien à transférer.

4.3. Compatibilité des imports — CONSERVÉE

La page accepte :
- format complet `nathalie-local-backup-v1` ;
- ancien export rapide `{app:'Nathalie is the best', data:...}` ;
- état brut contenant `schemaVersion`.

4.4. Protection de l’affichage des données importées — RENFORCÉE

La page de sauvegarde insérait le niveau lu dans le stockage local dans une zone `innerHTML`. Un JSON fabriqué manuellement pouvait théoriquement y placer du balisage HTML.

Correction V13.1 :
- échappement HTML explicite des champs venant du stockage/import ;
- messages d’erreur également échappés.

Test avec une valeur volontairement malveillante `<img ... onerror=...>` :
- aucun élément injecté dans le DOM ;
- aucun code exécuté ;
- la valeur apparaît uniquement comme texte.

4.5. Normalisation des objectifs hebdomadaires — CORRIGÉE

Ancienne incohérence :
- interface : 5–200 révisions et 0–20 missions ;
- normalisation d’une sauvegarde : autorisait 1–500 et 0–50.

V13.1 aligne désormais import, stockage et formulaire :
- jours : 1–7 ;
- révisions : 5–200 ;
- missions : 0–20.

Test sur valeurs extrêmes importées : 99 / -1 / 999 -> 7 / 5 / 20.

4.6. Stockage corrompu — OK

Un JSON principal volontairement invalide ne bloque pas le chargement : l’application revient aux valeurs par défaut.
Les objets de sauvegarde anciens ou mal formés sont normalisés avant utilisation.

6. PWA ET MODE HORS CONNEXION
============================================================

6.1. Installation trop fragile — CORRIGÉE

Ancien service worker V13 : `cache.addAll()` chargeait en bloc HTML + icônes + MP3 d’environ 5,5 Mo.
Si le MP3 ou une icône échouait temporairement, toute l’installation du service worker pouvait échouer.

V13.1 :
- shell essentiel : accueil, sauvegarde, manifeste -> obligatoire ;
- MP3 et icônes -> best effort via Promise.allSettled ;
- une panne d’asset optionnel ne bloque plus l’application hors ligne.

Test unitaire : échec simulé du MP3 pendant l’installation -> promesse d’installation résolue. OK.

6.2. Audio MP3 hors connexion / requêtes Range — CORRIGÉ

Les lecteurs audio demandent fréquemment des plages d’octets (`Range`). Le service worker sait maintenant créer une réponse HTTP 206 à partir du MP3 complet en cache.

Tests :
- bytes=0-99 -> 206, 100 octets ;
- bytes=100-199 -> 206, 100 octets ;
- bytes=-100 -> 206, 100 derniers octets ;
- plage hors fichier -> 416 avec Content-Range correct.

Cela rend la boucle et le déplacement dans le morceau beaucoup plus robustes hors connexion.

6.3. Cache des pages — CORRIGÉ

L’accueil et `sauvegarde-progression.html` gardent désormais des clés de cache distinctes. Une navigation réseau vers la page de sauvegarde ne peut plus remplacer par erreur la copie d’accueil.

6.4. Mise à jour
Nouveau cache : `nathalie-v13-1-auditfix-2026-08-31`.
Les anciens caches commençant par `nathalie-` sont supprimés à l’activation.
